ECOSYSTEM DOCUMENTATION & SPECIFICATIONS

The authoritative single source of truth for architectural contracts, configuration management doctrines, build protocols, craftsmanship standards, and active roadmaps across the Miqu desktop ecosystem.

OVERVIEW & PLATFORM BASE

Arch Linux Base

Author's Goal

A fully functional Wayland Desktop Environment is the ultimate goal. Progress is made methodically with strict adherence to architectural contracts, zero hidden magic, and total layer independence.

Platform Base

Currently developed and verified on an Arch Linux base. Standard Wayland protocols ensure compatibility across modern Linux distributions (Debian, Fedora, Alpine) without proprietary lock-in.

Zero Source-Code Defaults

Appearance tokens (colors, fonts, metrics, icon themes) must never have fallback magic literals in C++ struct initializers. All downstream apps implement a sync_defaults_from_toolkit() pattern.

CONFIGURATION MANAGEMENT GOLDEN RULES

Single-File Authority

Configuration management is the most critical architectural contract across the Miqu desktop ecosystem. It enforces absolute uniformity, predictable user customization, strict lifecycle safety, and zero hidden C++ magic.

The Uniform Two-Tier Ecosystem Architecture

┌────────────────────────────────────────────────────────┐
│ Tier 1: System Baseline (/usr/share/<app>/<app>.conf)  │
│  • Fully functional out of the box                     │
│  • Loaded ONLY if user config does not exist           │
└──────────────────────────┬─────────────────────────────┘
                           │ (when user invokes <app> --init-config)
                           ▼
┌────────────────────────────────────────────────────────┐
│ Tier 2: User Standalone (~/.config/<app>/<app>.conf)   │
│  • Generated on demand via '<app> --init-config'       │
│  • Safe timestamped archiving of existing config       │
│  • Loaded EXCLUSIVELY once it exists                   │
│  • Explicit 'source =' for dynamic themes/modules      │
└────────────────────────────────────────────────────────┘
RULE 1

Zero-Config Out of the Box

On a fresh system where ~/.config/<component>/<component>.conf does not exist, the component executes directly from the authoritative system baseline at /usr/share/<component>/<component>.conf. No configuration files are ever auto-seeded or written to ~/.config/ automatically on launch.

RULE 2

On-Demand Init & Safe Archiving

User configs are created strictly on-demand via <component> --init-config. If a config already exists, it is never silently overwritten: it is safely archived to <component>.conf.bak.<YYYYMMDD-HHMMSS> before a fresh template is placed.

RULE 3

Single-File Standalone Authority

Once ~/.config/<component>/<component>.conf exists, the component loads only that user file. There is no hidden C++ background inheritance, no implicit layered merging, and no silent magic.

RULE 4

Decoupled Dynamic Theming via `source`

miqutoolkit C++ contains zero hardcoded internal couplings to miqutheme. Users who want dynamic wallpaper palettes explicitly add source = ~/.config/miqutheme/current/miqutoolkit.conf. Static users simply define colors directly.

Canonical Component Lifecycle Sequence

All ecosystem binaries implement the uniform configuration lifecycle in pure C++20:

// 1. Resolve configuration path
std::string user_conf = FsUtils::get_user_config_file(app_name);
std::string target_conf = fs::exists(user_conf) ? user_conf : FsUtils::get_system_config_file(app_name);

// 2. Load exclusive configuration file (processes any internal 'source =' directives)
Config::get()->load_from_file(target_conf);

// 3. Register inotify watcher on loaded file and all sourced files for live reload
Config::get()->setup_config_watcher();

BUILD SYSTEM & INSTALLATION PROTOCOLS

Deterministic CMake & make.sh

1. The Standard `make.sh` Pattern

Every repository and downstream app provides a uniform, standalone make.sh script. It provides an idempotent local build for unprivileged users, and automatic system-wide installation to /usr when executed as root: 

# Local unprivileged build (into build/)
./make.sh

# System-wide install to /usr
sudo ./make.sh

2. Hierarchical Dependency Order

Components must be built strictly in their topological dependency order. The master orchestrator install_all.sh enforces this:

  1. 1 miquland — Compositor core & plugin headers
  2. 2 miqutoolkit — Shared C++20 UI framework
  3. 3 miqu-linux-apps — All 16 downstream utilities & daemons

CORE CRAFTSMANSHIP STANDARDS

Strict RAII & Zero Idle CPU

1. Strict Layer Sovereignty

Downstream apps never touch raw Cairo, Pango, or Wayland surface protocols directly. Reusable widgets are promoted into miqutoolkit.

2. Strict RAII & No Zombie States

Raw owning pointers are banned. File descriptors, Cairo contexts, and Wayland listeners are wrapped in scope-bound RAII guards with custom deleters.

3. Main-Thread Confinement

All Wayland protocol dispatches and Cairo rendering run strictly on the main thread. Background worker threads communicate exclusively via eventfd and pipes.

4. 0% Idle CPU Utilization

Compositor and applications sleep completely in the event loop when idle. Repaints are damage-driven; animation timers are torn down the moment transitions finish.

5. Zero Defensive Fallbacks

We maintain the entire stack end-to-end. Never introduce speculative fallback branches for capabilities we natively control and guarantee across our own codebase.

6. Radical Candor & Real Protocols

State hard protocol or low-level limitations upfront. Zero pseudo-solutions or fabricated APIs. Architectural prerequisites precede implementation.
