Quick Installation

Option 1: Recursive Workspace 
git clone --recurse-submodules https://github.com/miqu-project/miqu-project.git
cd miqu-project
sudo ./install_all.sh
Option 2: Individual Build / CMake 
git clone https://github.com/miqu-project/miquland.git
cd miquland
./make.sh         # local build
sudo ./make.sh    # system install (/usr)

cmake -B build -DCMAKE_INSTALL_PREFIX="/usr"
cmake --build build -j"$(nproc)"
sudo cmake --install build

AI, Code & Trust

Let's be totally honest about AI. Here is where it fails, why we still use it to type fast, and how we actually keep Miqu memory-safe and private.

Genuine, Documented Issues with LLM Coding

Hidden Vulnerabilities

LLMs frequently generate plausible-looking code that omits basic input validation or memory-safety checks, introducing subtle bugs like integer overflows, off-by-one errors, and deprecated cryptographic suites.

Hallucinated Dependencies

Models occasionally fabricate package names and function signatures. Attackers actively register these hallucinated package names on public registries to inject malicious code directly into automated build pipelines.

Flow Disruption

Meticulously verifying confident but subtly flawed code often takes more time than authoring it from scratch. This forces engineers into a passive reviewer/auditor role, breaking the deep focus of active programming.

Licensing & Data Leaks

Models regularly output verbatim memorized code without attribution, risking unintended GPL or MIT license violations. They can also surface configuration tokens and private identifiers embedded in public training datasets.

Skill Degradation

Excessive reliance on AI deprives developers of the iterative problem-solving and debugging struggles needed to build deep first-principles intuition, reducing their ability to critically evaluate software.

Data Starvation

Widespread AI adoption has caused a noticeable drop in organic questions on public developer forums. This deprives future models of fresh human knowledge, raising the risk of recursive model collapse.

Minimal Viable Implementation

When asked for a high-level outcome (e.g., displaying "Hello World"), models may architect middle-layer classes like a TextView widget. Because the user never specified requirements for that intermediate layer, the model may implement only the bare minimum needed for the prompt—leaving the abstraction half-done and missing core features like multiline wrapping.

God Classes & Redundant Reinvention

Lacking repository-wide awareness, models frequently dump all responsibilities into giant monolithic classes ("God Objects"), or author completely separate, parallel classes with redundant boilerplate instead of properly extending or composing with existing abstractions.

Code Churn & Cascading Rewrites

When structural flaws surface in AI-generated systems, surgical refactoring is often unfeasible due to opaque interdependencies. Instead of incrementally fixing the foundation, developers are pushed into a total bottom-to-top overhaul, causing extreme code churn where codebases are repeatedly rewritten rather than steadily evolved.

Weighing the Criticisms of AI Code Generation

The Historical Precedent

Every evolution in tooling was once attacked as "not real programming." Assembly programmers claimed high-level compilers produced lazy bloat; later critics attacked IDE autocompletion and Stack Overflow. Theoretical purism always concedes to pragmatic leverage.

The Purity Trap

Purists confuse keystrokes with engineering. Typing syntax by hand is manual labor; engineering is defining architecture, memory boundaries, and state machines. Discrediting software merely because an accelerator typed the boilerplate is gatekeeping, not craftsmanship.

If Boilerplate Is Not the Issue, What Is Its Extent?

Critics often concede that using AI for "mere boilerplate" is fine. But where does boilerplate end? When an IDE like Android Studio scaffolds an entire complex Activity with lifecycles and navigation—leaving a developer to merely fill in text and image assets—the entire application is boilerplate. If that is acceptable, can a window manager's protocol loops and event dispatches also be framed as boilerplate and handed to an LLM? The boundary is completely arbitrary.

Big Tech's Black Boxes

Proprietary software giants openly write 50%+ of their code with AI, shielded behind closed-source binaries without public scrutiny. Open-source builders use the exact same accelerators but face performative outrage simply because their git history is transparent.

The Open-Source Irony

Major ecosystems, including the Linux kernel, routinely merge machine-assisted patches as long as they survive human review and strict test suites. The loudest critics demanding "pure hand-typed" code are actively relying on software built with machine assistance.

The "Clean Code" Double Standard

Human-written code has always been famously messy, held together by the age-old rule: "If it works, don't touch it." Multi-million-dollar cult games and foundational tools have shipped on giant ladders of nested if statements and duct-taped scripts without outcry. Yet critics hold AI code to a superhuman purity test—demanding textbook design patterns and pristine refactorability that most production human code never met in the first place.

The "Omarchy" Adoption Hypocrisy

Pioneers of anti-AI rhetoric quickly rushed to praise and hype distributions like Omarchy—a desktop openly driven by vibecoded plugins and deep agentic AI modifying system dotfiles and diagnosing crashed processes. When packaged attractively, even vocal critics quietly embrace agentic automation directly inside their OS. How many purists are genuinely surviving their own standards?

The Calculator Dilemma: Purity vs. Sovereignty

Which would you prefer: an AI-assisted offline calculator, or a closed-source Big Tech calculator that phones home and connects to the internet? An artisanal, human-written offline tool is ideal in theory—but what if its design clashes with your desktop, fails to sync with your system theme, or lacks modern Wayland ergonomics? When off-the-shelf software doesn't fit your environment, using AI to curate a lightweight, 100% offline utility tailored precisely to your own system is the most pragmatic, privacy-respecting choice available.

Who Is a Developer?

Where Does the Boundary Lie?

How much abstraction is allowed before someone stops being a developer? Where is the line actually drawn? Does it require writing raw C code against kernel syscalls? Is it authoring the window manager from scratch? Or does scripting an installer that downloads prebuilt compositors, status bars, and widgets—and stitches them all together—still count?

Every developer stands on someone else's abstraction. The question is: where does using tools end, and building software begin?

The "Rice in an ISO" Paradox

Consider a familiar scenario: someone takes Arch Linux as an OS base, Hyprland as compositor boilerplate, Quickshell as shell boilerplate, a community riced config as UI boilerplate, and packages it all into an ISO. Are they a software developer, a desktop environment creator, or a distribution maintainer?

If assembling layers of existing binaries and riced configurations into an installer is celebrated as building an OS or desktop, why should engineering native C++20 daemons and custom Wayland protocols be questioned simply because an LLM assisted with boilerplate?

When boilerplate is layered on top of boilerplate, who decides which layer confers the title of "developer"?

How We Keep It Safe

Strict C++20 RAII

AI writes memory leaks. We counter this structurally. Raw owning pointers are banned. Every surface and context is scope-bound. Memory leaks become physically impossible by design.

Zero Tolerance Build

Code compiles with `-Wall -Werror`. A single compiler warning fails the build. AddressSanitizer runs automatically to catch anything the AI or the human missed.

0.0% Idle CPU

AI loves infinite polling loops. We ban them. Without user input or screen damage, the entire ecosystem sleeps cleanly at 0% CPU in the Wayland event loop.

Strict Protocol APIs

Wayland forces convergence. There is only one mathematically correct way to execute a scenefx blur pipeline. The code looks identical to other repos because the physics demand it.

100% Offline

Zero telemetry. Zero tracking. The ecosystem doesn't link to network libraries. It runs entirely offline. Your data never leaves your machine.

Fully Public

Under the MIT License, every line of code is exposed. Anyone can audit the architecture, test the security, and verify we actually follow our own rules.
