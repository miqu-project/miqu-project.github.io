GitHub
  • Dynamic Tiling & Floating: Full binary dynamic tiling, floating window rules, and multi-monitor output tracking.
  • C++20 & Scenefx Visuals: Hardware dual-kawase blur, rounded window corners, soft drop shadows, and gradient borders built on wlroots and scenefx.
  • Wayland Protocol Suite: Native support for xdg-shell, wlr-layer-shell-v1, ext-session-lock-v1, and ext-idle-notify-v1.
  • Absolute 0% Idle CPU: Strictly damage-driven repaints (wlr_output_schedule_frame), instant animation timer teardown, and zero busy polling.
  • Compositor IPC Socket: High-speed Unix domain socket controller (miquctl) for runtime queries, window manipulation, and dynamic dispatching.
  • TTY & Display Manager Ready: Direct invocation from virtual terminal (TTY) or standard session registration with miqudm, SDDM, or GDM.

miqutoolkit

GitHub
  • C++20, Cairo & Pango Engine: Clean object-oriented vector drawing and layout widgets (ViewGroup, CardView, Label).
  • Two-Tier Single-File Authority: System baseline in /usr/share/ with on-demand user configs via --init-config and safe timestamped backups.
  • Decoupled Dynamic Theming: Transparent source = directives with automatic inotify file watchers for instant live reload.
  • Strict RAII & Pointer Safety: Scope-bound smart pointers with custom deleters; zero raw owning pointers or memory leaks.
  • Thread Safety & Event Isolation: UI rendering strictly confined to main thread; background workers communicate safely via eventfd and pipes.
  • Zero UI Fragmentation: Shared widgets, metrics, and styling tokens unifying all 16 ecosystem applications.

ecosystem guide & architecture

documentation

Welcome to Miqu. This guide walks you through how Miqu is designed, how configuration works, how components communicate, and how to build and extend the desktop environment.

overview & platform base

Our goal with Miqu is simple: build a complete, cohesive, and modern Wayland desktop environment from the ground up. Instead of gluing together disparate tools with conflicting styles and heavy background services, Miqu gives you a unified ecosystem where every application shares the exact same design language, configuration model, and lightweight performance philosophy.

We develop and test Miqu primarily on Arch Linux. Because everything is built on open Wayland standards via wlroots, Cairo, and Pango, the entire desktop compiles and runs cleanly across other modern Linux distributions without vendor lock-in.

“A fully functional desktop environment is our goal, and we make steady progress by adhering to clean code, clear boundaries, and zero hidden magic.”

how configuration works

Configuration management can easily become messy if not carefully planned. Many desktops scatter settings across hidden databases, layered overrides, or opaque background daemons. In Miqu, we follow a straightforward two-tier model that keeps your configuration predictable, safe, and completely transparent.

1. Zero-config out of the box

When you install Miqu, every application works immediately out of the box. Applications read directly from authoritative system defaults in /usr/share/<app>/<app>.conf. We never pollute your home directory or auto-create files in ~/.config/ until you explicitly ask for them.

2. On-demand initialization with safe archiving

Whenever you are ready to customize an application, simply run: 

<app-name> --init-config

This writes a fresh, fully documented configuration template to ~/.config/<app>/<app>.conf. If you already have an existing configuration, it is never silently overwritten—it is safely backed up with a timestamp (.bak.YYYYMMDD-HHMMSS) before the new template is written.

3. Single-file authority

Once your user configuration exists, the application reads only from that file. There is no silent fallback merging in C++ code where missing values secretly revert to hardcoded values. What you see in your configuration file is exactly what gets applied.

4. Decoupled dynamic theming

Dynamic theming is completely decoupled from our C++ UI toolkit. If you want dynamic color palettes generated from your wallpaper via miqutheme, you include this line in your config: 

source = ~/.config/miqutheme/current/miqutoolkit.conf

Sourced files are automatically watched via inotify. Whenever your wallpaper or theme changes, all running apps reload colors live without needing a restart. If you prefer fixed, static colors, you can simply remove or comment out the source line and define colors directly.

build system & installation

Building software should never be a mystery. Every repository in Miqu includes a standardized ~20-line make.sh script so the workflow is identical across all components:

Building locally: Run ./make.sh as a normal user. It configures CMake and builds into a local build/ directory without touching your system.

Installing system-wide: Run sudo ./make.sh. It automatically compiles and installs binaries, assets, desktop entries, and icons directly to /usr.

One-command full ecosystem install: In the root workspace repository, running ./install_all.sh compiles and installs everything in correct topological order:

git clone --recurse-submodules https://github.com/miqu-project/miqu-project.git
cd miqu-project
./install_all.sh

core craftsmanship standards

We adhere to strict engineering disciplines across our C++20 codebase to make sure the desktop remains stable, performant, and maintainable:

  • Small, single-responsibility functions: Functions stay around 40–50 lines. Geometry math, state validation, and rendering routines are broken into clear helpers rather than monolithic blocks.
  • Strict RAII and pointer safety: Raw allocations, file descriptors, Cairo contexts, and Pango layouts are immediately bound to RAII guards or std::unique_ptr. No resource leaks, no zombie states.
  • Zero idle CPU usage: Everything is event-driven. When there are no input events, damaged scene buffers, or running animations, the compositor and apps sleep completely in the Wayland event loop at 0.0% CPU.
  • Main-thread UI confinement: Wayland protocols and rendering run strictly on the main event-loop thread. Background worker threads communicate cleanly via pipes or eventfd rather than touching UI widgets directly.
  • Toolkit sovereignty: Client applications never bypass miqutoolkit to draw raw surfaces directly. When an app needs a new UI control, we build it directly inside the toolkit for everyone to use.

code integrity & transparency

ai use & code safety

A clear, honest look at how AI tools are used in Miqu, what software authorship actually means, and the safety rules that keep our code secure, offline, and auditable.

ai use and software authorship

A common question today is: If you use an AI assistant to write code, are you still the author of the project? To answer this honestly, we have to look at how software has always been built.

layers of abstraction in modern programming

When you create an Android app and use a TextView, you did not write the text rendering engine, the font rasterizer, or the graphics drivers. You used existing tools to build your idea.

If using pre-existing tools meant you were not an author, then almost no one today could be called a software developer. Unless you personally design the computer chip, write the kernel drivers, and type raw assembly instructions directly to the hardware, you are always building on top of someone else's work.

assembling an iso vs. building from scratch

Consider the difference between assembling and building. If someone takes Arch Linux, adds Hyprland and Quickshell, configures a nice theme, and packages it into an ISO, they are the curator and maintainer of that ISO. But they did not write the window manager, the toolkit, or the core apps.

In Miqu, we did not just package existing tools. We wrote our own Wayland compositor (miquland), developed our own C++20 graphics toolkit (miqutoolkit), and built 16 native applications. We use AI as a tool to speed up typing repetitive boilerplate, event handlers, and protocol bindings.

authorship is architecture and accountability

Typing characters on a keyboard is not what makes someone an engineer. Authorship is about design, architecture, and taking full responsibility for the system:

An architect designs a building's foundations, load-bearing walls, and fire exits without pouring every bucket of concrete by hand. In Miqu, the human developer is that architect: deciding every interface, choosing the algorithms, setting memory safety rules, and testing every commit on physical hardware.

code safety and memory management

AI tools can make mistakes if left unchecked. To prevent bugs and security issues, every piece of code in Miqu must follow strict technical rules:

  • Automatic cleanup (strict RAII): Raw pointers are not allowed to manage memory. Every file handle, graphics context, and system resource is wrapped in modern C++ smart pointers or automatic cleanup guards. This guarantees no memory leaks.
  • Completely offline (zero telemetry): Miqu never phones home. There are no tracking scripts, analytics, or background internet connections. The desktop works 100% offline.
  • Strict compiler checks: Code must compile without warnings using strict flags (-Wall -Wextra -Werror). We also run memory safety tools (AddressSanitizer and UndefinedBehaviorSanitizer) to catch hidden bugs before anything is merged.
  • Zero idle CPU usage: Applications sleep completely when not in use. There are no background polling loops wasting battery or heating up your processor.

testing, audits, and consistency

Because Miqu consists of 18 repositories, keeping code uniform is essential:

  • Automated code audits: We run automated scans to check for security flaws, memory leaks, and protocol errors across all repositories.
  • One single rulebook: Every application follows the exact same architecture guidelines documented in our public AGENTS.md file. This ensures every app behaves consistently.

transparency and closed-source software

Today, most major tech companies publicly admit that a large portion of their code is generated by AI. However, their operating systems (like Windows and macOS) are closed-source. You cannot inspect their code, see how it was written, or verify what it does with your private data.

Proprietary software avoids scrutiny simply by hiding its source code. In Miqu, we believe in complete transparency: we openly explain how we use AI tools, and every single line of our code is 100% open-source. Anyone can read, audit, and verify our work on GitHub.

how to trust ai-assisted software

“You should only trust AI-assisted software if it never connects to the internet on its own, and if you have the full freedom to read and audit every line of code.”

We designed Miqu to meet this standard with two simple, factual guarantees:

1. Complete network independence: The desktop never connects to the internet on its own. There are no background telemetry pings, hidden analytics, or automatic cloud connections. Network activity happens only when you intentionally open an internet application.

2. Fully public source code: Every line of C++20 and Wayland code is public under the MIT license. You have the right to audit, build, and modify the code yourself.
